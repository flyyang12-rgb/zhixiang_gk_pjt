# 知向高考志愿推荐网站需求文档

## 1. 产品定义

### 1.1 目标

建设一个本地可运行的高考志愿推荐 MVP，帮助家庭基于录取位次、选科要求、院校层次、专业与就业证据形成可解释、可追溯的候选清单。

### 1.2 MVP 成功标准

以下能力全部可用才视为 MVP 完成：

1. 创建并管理多个学生档案。
2. 基础信息保存后直接进入专业就业工作台，展示九个可解释专业卡片。
3. 查询全国院校地图和院校详情。
4. 河南、山东、河北考生可基于真实位次生成候选清单。
5. 分别查看院校候选、专业候选和交叉匹配。
6. AI 顾问能够结合当前档案解释推荐结果。
7. 导出完整 PDF 报告。
8. 查看招生数据的年份与来源。

### 1.3 边界

- MVP 仅在开发者本机运行，不提供注册、支付、云同步或公开访问。
- 系统生成候选清单，不生成或冒充省考试院正式志愿表。
- 所有结果仅供决策参考，不承诺录取或就业结果。
- 当前数据库包含全国院校基础名单，并重点覆盖河南、山东、河北 2023—2025 年部分可追溯招生数据；缺口必须显式披露。

## 2. 用户与使用流程

### 2.1 目标用户

- 主要决策者：高考学生家长。
- 共同参与者：高考毕业生。
- 数据维护者：本地系统管理员。

### 2.2 核心流程

1. 家庭选择“目标探索”或“志愿填报”，创建学生档案并填写省份、科类、分数；志愿填报模式填写可靠位次。
2. 系统直接进入专业就业工作台，先按硬约束过滤，再展示优先了解、值得比较、谨慎报考各三个专业。
3. 每个专业展示最近三十天全国招聘覆盖、三个就业方向、学历门槛、四项评分依据和风险。
4. 用户展开专业后查看真实招生单元对应的冲刺、稳妥、保底院校各最多两所；目标探索模式不显示冲稳保。
5. 用户可收藏或排除专业和学校，并把学校保存为目标院校；每所学校提供学校官网和招生官网。
6. 不设置测评、答题或家庭偏好入口，建档后直接进入专业与学校工作台。
7. AI 顾问只解释、比较和回答规则结果，不新增专业、不改变排名或冲稳保。
8. 客户端和 API 启动时只读取已保存的就业统计；只有本机管理员明确手动触发才采集，数据超过七天未更新时停止参与排名。
9. 系统导出包含依据、来源和免责声明的 PDF 报告。

## 3. 功能需求

### 3.1 学生档案

- 支持创建、重命名、继续编辑、复制和永久删除档案。
- 保存学生基础信息、收藏、排除项、推荐结果和顾问会话；历史问卷与家庭偏好数据保持兼容但当前界面不再提供入口。
- 分数必须校验所在省份当年满分范围。
- 位次可选；未填写时进入目标探索模式，不生成冲稳保或录取预测。
- 用户可随时重新计算，历史结果保留生成时间和数据版本。

### 3.2 历史兼容数据隔离

- 当前版本不提供测评、答题、家庭条件、家庭偏好或共同权重入口。
- 既有 `profile_assessments`、`profile_preferences` 与兼容接口仅用于不破坏旧档案，不参与完成度、专业排序、冲稳保、顾问或 PDF。
- 不得根据旧表仍存在而恢复已删除页面。

### 3.5 全国院校地图

- 使用 ECharts 中国地图，不依赖商业地图服务。
- 全国视图展示各省院校数量和层次分布，点击省份进入院校列表。
- 支持按 985、211、双一流、本科、专科、城市、专业和学校名称筛选。
- 一本、二本仅作为历史招生批次展示，不作为全国统一院校属性。
- 院校详情展示学校属性、城市、优势专业、面向当前省份的招生单元、三年录取记录和来源。
- 点击地图、工作台、候选结果或收藏中的学校时，统一在当前页面右侧打开详情抽屉；关闭后保留原筛选和滚动位置。
- 学校详情和专业详情各提供三条基于本地证据的简短解读；深入问题只预填到顾问输入框，不自动发送。
- 只有带官方专业名称、认定类型、发布方、官方来源和核验时间的优势专业证据才可展示；有逐专业认定年份时展示认定年，否则明确标记综合名录年份；无证据时明确为空。
- 地图和 ECharts 按需加载，首次进入两步工作台时不下载地图代码。

### 3.6 地区建议、院校候选和专业候选

- 当前版本不收集地区或家庭偏好；院校候选以同省、同科类、同制度年份位次为主。
- 专业候选结合选科要求、招生证据、培养成本、深造路径和就业方向形成。
- 最终交叉匹配只保留院校实际开设、且在当前省份和年份存在招生资格的招生单元。
- 候选清单默认提供约 24 所院校：冲刺约 6 所、稳妥约 12 所、保底约 6 所；数据不足时允许少于该数量，不得填充虚假候选。
- 每所院校展示匹配专业、不推荐专业、推荐原因、风险因素、数据年份和推荐置信度。

### 3.6.1 专业就业工作台

- 首屏固定展示九张专业卡片：优先了解三个、值得比较三个、谨慎报考三个；证据不足时允许少于九个，不凑数。
- 专业评分为全国招聘覆盖 40%、本科可直接进入岗位比例 25%、当前位次可进入合理培养院校 25%、行业稳定性与替代风险 10%。
- 推荐前必须过滤选科不符和已确认的特殊要求；缺少专业—院校交叉证据时保留专业方向，将院校因子标记未知并披露证据覆盖度，不得按 0 分处理或清空全部专业。
- 每个专业关联一个就业大类和三个标准岗位方向；岗位归类使用人工审核的专业—岗位映射，AI 无权决定分类。
- 招聘覆盖只使用最近三十天去重后的公开岗位；原始岗位保存三十天，匿名每日统计长期保存。
- 招聘数据仅由本机管理员明确手动触发采集；服务端定时器和客户端启动均不自动同步。超过七天未成功更新、只剩单一来源或质量异常时不得输出全国覆盖结论。
- 招聘来源至少覆盖官方公共招聘、允许公开访问的综合招聘页面和企业官网；遵守平台条款，不绕过登录、验证码或访问限制。
- 同一岗位按公司主体、标准岗位方向、城市、学历要求和发布时间区间去重，企业官网记录优先。
- 志愿填报模式先独立展示同省、同科类的学校/招生单元冲稳保各最多两所；只有具体专业记录或经核验的专业组成员才能进入专业卡交叉匹配，不以学校线或专业组名称冒充具体专业。
- 河南 2025 单年专业组按考生位次/专业组最低位次计算：不高于 0.80 为保、0.80—0.95 为稳、0.95—1.15 为冲，超过 1.15 不自动推荐；统一标记低置信度，不与 2023—2024 文理科混算。
- 每所学校提供经核验的学校官网与招生官网；链接失效时标记待核验，不替换为搜索结果。
- 目标探索模式允许收藏专业和目标院校，但不生成冲稳保或录取预测。
- “我的收藏”允许选择 2—4 所目标院校，紧凑比较城市、层次、当前档案招生位置、选科要求和数据缺口。对比下方自动输出三行 AI 解释，不要求用户再输入问题；失败时回退本地规则结果。
- 工作台可记录模考名称、日期、分数、全省位次和备注。新记录默认成为当前坐标；删除时恢复最近一条。只有分数没有位次不得生成冲稳保。
- 收藏专业和学校可保存最长 500 字家庭讨论备注；备注只辅助沟通，不是推荐权重。
- 收藏中选择 1—4 所学校后可打开“给爸妈看”一页简报，并复制为纯文本。它不生成公网链接，不上传家庭数据。

### 3.7 AI 升学规划顾问

- 顾问名称固定为“知向规划顾问”或“升学规划顾问”，表达像一位懂现实的班主任：先接住顾虑，再明确判断。
- 内部只加载锁定版本的 MIT `alchaincyf/zhangxuefeng-skill` 安全改编方法论，保留来源、提交版本、许可证和改编说明；运行时不加载原版角色提示词。
- 使用就业倒推、普通毕业生的中位结果、家庭承受能力、城市机会、培养年限和转行成本等框架。
- 可以尖锐批评错误选择、宣传话术和侥幸心理，但必须“批评选择不攻击人”，删除辱骂、歧视、制造焦虑、唯收入论和真人身份模仿。
- 规则引擎是推荐结果唯一生产者；AI 只能追问、解释、比较和指出数据缺口。
- 每次回答前重新读取当前学生档案、专业工作台、候选清单和本地招生数据；数据库事实优先于旧聊天回答。
- 同一会话永久保存消息，并向回答服务提供滚动记忆摘要、最近 16 条消息和当前问题；摘要只能压缩用户已说条件、讨论对象和待办，不能产生新事实。
- 回答必须先接当前问题：问候、身份问题和“能不能报某专业”等单点短问题用约 100—250 字自然回答，不强制标题、不逐字复述前文、不绕到无关专业；复杂比较和风险分析才使用“先说结论—为什么这么说—最容易踩的坑—接下来怎么查”，通常 300—500 字，最多追问两个会改变判断的问题。
- 从院校详情进入时，顾问页面显示正在讨论的院校；请求携带院校 ID，服务端重新读取该校面向当前档案的招生记录、风险、来源和数据缺口。前端不得提交院校事实，打开页面不得自动发送。
- 从专业或院校详情进入时先打开未保存草稿并预填问题，第一次发送时才原子创建会话和用户消息；历史会话使用自身焦点决定返回的专业或院校详情。
- 学校焦点只限定事实范围，不能让每轮回复都变成相同学校介绍。用户表达目标专业时先核对该校的具体专业招生证据；用户指出重复或答非所问时，先承认并接回最近的明确目标。
- 历史记录每页 20 条，展示类型、标题、最后消息、消息数和更新时间；消息使用游标向上翻页。删除单个会话必须二次确认。
- 发送使用 `clientMessageId` 幂等保存；网络或数据库失败时在原问题下提供“重新发送”，不得伪造顾问回复。
- 用户未清除院校焦点前，后续追问继续使用该院校上下文；普通顾问入口不默认绑定任何院校。
- 历史问卷与家庭偏好数据不得进入当前顾问上下文。
- 涉及事实的数据必须显示年份与来源；无数据时明确说明未知。
- 使用 OpenAI 兼容接口，通过 `AI_BASE_URL`、`AI_API_KEY` 和 `AI_MODEL` 配置。
- AI 请求 15 秒超时；未配置、超时、限流、无效结构或越界时使用相同语气和结构的本地解释。
- 页面明确说明聊天保存在本机 MySQL；配置外部 AI 后，仅把回答当前问题需要的最少上下文发给该服务，不发送数据库密码、API Key 或无关档案。

### 3.8 PDF 报告

- 报告包含学生基础信息、地区建议、院校候选、专业候选、交叉匹配、风险提示、数据来源和免责声明。
- PDF 内容必须与用户当前保存的候选清单一致。
- 支持浏览器打印；MVP 不导出 Word 或 Excel。

### 3.9 本地数据管理

- 管理页面仅允许本机访问，不出现在普通用户导航中。
- 支持标准 CSV 导入、字段校验、预览、确认、冲突提示和单次导入回滚。
- 保存原始来源、采集时间、数据年份和导入批次。
- 导入报告展示新增、更新、跳过、缺失和异常记录数。
- 所有导入使用唯一键更新，重复执行不得产生重复记录。
- `/admin/data-quality` 只允许直达访问，不进入普通导航；展示官网、招生网、优势专业和招生年份的数据库实时覆盖率与逐校缺口。
- 招生记录保存学历层次、招生类别、批次、计划类型、资格要求、推荐资格、原始名称与稳定业务键；同校同年不同批次、计划和招生单元必须能并存。
- 每个来源文件登记官方页面、下载地址、必要的镜像披露、发布时间、采集时间、SHA-256、只读本地路径和文件大小。
- 导入必须输出原始、有效、重复、未匹配、拒绝、新增和更新数量；四类逐行结果之和必须等于原始有效行数。默认只生成预检批次，显式确认后才事务提交，并可按批次回滚。
- 三省 2023—2025 的本科、专科及各批次以审计状态闭环。没有取得官方材料、尚有未匹配记录或 OCR 置信不足时标记待核验，不以虚构记录补齐。
- 学校详情可浏览普通与特殊批次；只有普通类主批次、普通计划且有可靠最低位次的记录可进入自动冲稳保。
- 学校链接自动发现只写入 `.scratch` 候选与报告；人工复核后才能显式导入，失败不得覆盖已有有效事实。

## 4. 数据与推荐规则

### 4.1 数据来源优先级

1. 教育部全国高等学校名单。
2. 河南、山东、河北教育考试院。
3. 院校官方招生网站。
4. 其他来源只能辅助定位，不可直接进入正式推荐数据。

### 4.2 推荐原则

- 使用全省位次而非裸分作为主要录取比较指标。
- 必须区分省份、年份、科类、批次和招生单元。
- 冲稳保阈值根据近三年位次分布和波动计算，不使用固定分差。
- 缺少位次、年份不足或招生规则变化时降低推荐置信度。
- 数据不足的院校可以展示，但不得进入自动冲稳保结果。
- 任何结果均不得使用“必录”“稳录”或确定录取概率等措辞。

## 5. 技术与接口要求

### 5.1 技术栈

- 前端：Vue 3、TypeScript、Vite、ECharts。
- 后端：Node.js、Express、TypeScript、Zod、`mysql2`。
- 数据库：本地 MySQL 8，数据库名 `zhixiang`。
- 本地启动：`npm install`、`npm run db:init`、`npm run dev`。
- MVP 不使用 Docker；架构不得阻碍后续公网部署。

### 5.2 API

- `GET /api/schools`：筛选和分页查询院校。
- `GET /api/schools/:id`：院校、招生单元和录取记录详情。
- `GET /api/map/provinces`：地图院校数量与层次聚合。
- `GET /api/admin/school-data-quality`：本地维护覆盖率和待核验院校分页列表。
- `POST /api/profiles`：创建学生档案。
- `GET /api/profiles/:id`：读取完整档案。
- `PATCH /api/profiles/:id`：更新档案。
- `DELETE /api/profiles/:id`：永久删除档案及关联数据。
- `GET|POST /api/profiles/:id/score-snapshots`：读取模考轨迹或新增当前坐标。
- `DELETE /api/profiles/:id/score-snapshots/:snapshotId`：删除模考坐标并在必要时恢复上一条。
- `GET /api/profiles/:id/profession-dashboard`：返回专业工作台、只读 `profileSummary`、模考坐标和收藏备注。
- `PATCH /api/profiles/:id/saved-items/:itemType/:itemId/note`：保存或清除家庭讨论备注。
- `POST /api/profiles/:id/recommendations`：生成或重新生成推荐。
- `POST /api/profiles/:id/advisor/messages`：发送顾问消息。
- `GET /api/profiles/:id/advisor/conversations?page=&pageSize=`：分页查看有消息的历史会话。
- `POST /api/profiles/:id/advisor/conversations`：使用 `{ focus, initialMessage, clientMessageId }` 首次发送并原子创建会话。
- `GET /api/profiles/:id/advisor/conversations/:conversationId/messages?beforeId=&pageSize=`：游标读取消息。
- `POST /api/profiles/:id/advisor/conversations/:conversationId/messages`：使用 `{ message, clientMessageId }` 幂等发送。
- `DELETE /api/profiles/:id/advisor/conversations/:conversationId`：只删除当前档案下的指定会话。
- `POST /api/profiles/:id/advisor/comparison`：对 2—4 所已选院校生成不写入聊天历史的简短对比分析。
- `GET /api/profiles/:id/report.pdf`：生成 PDF 报告。
- `POST /api/admin/imports`：预检数据导入。
- `POST /api/admin/imports/:id/commit`：确认导入。
- `POST /api/admin/imports/:id/rollback`：回滚导入。

统一响应结构为 `{ success, data, error, requestId }`。所有输入使用 Zod 校验，SQL 使用参数化查询，列表接口强制分页。

## 6. 非功能需求

- 密码和 AI Key 仅存于 `.env`，不得进入前端、日志或版本库。
- 应用使用最小权限数据库账号，`root` 只用于初始化。
- 档案、收藏和聊天记录仅存本地，并提供一键永久删除。
- 关键页面在常见桌面和移动尺寸下可用。
- 数据库或 AI 连接失败时提供中文诊断，不显示 SQL、密钥或服务器堆栈。
- 同一数据版本和学生档案必须产生稳定一致的规则推荐结果。

## 7. 验收场景

1. 河南考生填写真实位次后直接生成包含冲稳保的全国院校候选清单。
2. 山东考生未填写位次，系统使用一分一段表估算并标记粗略参考。
3. 河北历史类考生选择不接受某地区，该地区院校不进入交叉匹配。
4. 用户不需要完成任何问卷即可查看专业、学校和冲稳保解释。
5. 家庭可支持家业接续，系统允许相关专业进入候选，但仍展示培养与机会成本。
6. 某院校只有两年有效数据，系统降低置信度并说明缺失年份。
7. AI 被问及数据库不存在的录取位次时明确表示无数据，不编造答案。
8. 用户删除学生档案后，关联测评、推荐和聊天记录全部删除。
9. 同一 CSV 重复导入不产生重复记录，并可回滚最近一次确认导入。
10. 导出的 PDF 与当前收藏、排除和排序后的候选清单一致。
