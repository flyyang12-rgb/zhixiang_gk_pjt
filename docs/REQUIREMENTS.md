# 知向需求与验收

本文件配合 [SPEC](SPEC.md) 使用，核对日期为 2026-09-05。产品规则以 SPEC 为准；下列“当前能力”用于交接，待实现项目单独列出，不能因写进需求就当成已经上线。用户操作见 [使用指南](USER_GUIDE.md)。

## 1. 产品定义

面向高考学生和家长，根据可核验招生、专业与就业证据形成候选清单，供家庭讨论。规则引擎负责生成、排序和冲稳保，升学规划顾问负责解释，不提供录取、就业、收入或升学保证。

- 主流程只有“基础信息 → 专业与学校”，不提供双视角、测评、答题或家庭偏好入口。
- 不注册、不登录，全部档案、收藏和聊天公开共享，所有访客都能查看、修改和永久删除。
- Vue 只经 Express API 访问服务端；正式数据保存在新加坡 Supabase PostgreSQL，密钥不进入前端。
- 全国院校基础名单与部分河南、山东、河北 2023—2025 招生记录可用，未完整覆盖全部年份、科类、批次和专业。
- 不直接生成或提交省考试院正式志愿表。正式填报必须复核当年招生计划、选科要求和院校章程。
- Docker、本地桌面安装包、账号隔离、支付及其他省份完整录取推荐不在当前范围。

## 2. 用户流程

1. 创建或从公开历史列表选择学生档案。
2. 填写称呼、省份、科类和选科；目标探索可不填分数/位次，志愿填报填写分数，可靠位次未知则留空。
3. 保存后进入工作台；先看规划位次和可核验学校，再比较专业方向。
4. 收藏学校/专业，按需排除或恢复专业、添加备注、比较学校。
5. 从具体学校或专业预填问题到顾问，用户确认发送后才保存会话。
6. 通过家庭简报或 PDF 讨论已有证据；缺失内容按当前报告限制披露。

## 3. 当前功能要求

### 3.1 档案与模考

- 当前支持新建、切换、永久删除，以及记录模考与更新位次；没有完整资料编辑、复制和重命名入口。
- 建档原始 planning_mode 保留。后续形成规划位次时自动开启学校推荐，不要求重建或手动切模式。
- 未知分数/位次使用 null，不转为 0；当前分数输入范围为整数 100—750，位次必须为正整数。
- 每次模考保存名称、日期、分数、全省位次及备注；新记录成为当前坐标，删除当前记录后恢复最近一条。
- 规划位次取最近最多 5 次有效全省位次的中位数，展示样本数、波动区间和稳定度。只记录分数的考试不参与计算，历史有效位次仍可继续使用。
- 不把班级/校内排名、平均裸分或趋势外推当成可靠高考位次。

### 3.2 专业工作台与学校候选

- 先按选科等硬条件过滤，再使用确定性规则排序。
- 专业每档最多 3 个，共最多 9 个；每专业最多 3 个已审核就业方向。证据不足时少展示，不凑数。
- 因子权重为近期招聘覆盖 30%、本科直接就业入口 20%、可达院校 25%、近期需求稳定性 10%、未来发展证据 15%。
- 至少两个独立因子有效且证据权重覆盖达到 50% 才显示综合参考分；否则“暂不评分”。未知不计为 0。
- 未来证据必须有发布方、年份、官方来源、核验时间和有效期；过期停止参与排序。
- 招聘覆盖只代表最近 30 天去重公开岗位样本，不等于就业率或收入。健康来源不足两个、超过七天或质量异常时停止就业排名。
- 招聘只由维护者明确手动采集；浏览器/API 启动不自动同步，不绕过登录、验证码、412 或访问控制。
- 当前学校候选按冲、稳、保每档最多 2 所；专业卡展示可核验学校数并预览最多两所。没有规划位次时只探索和收藏。
- 招生记录区分 exact_major、major_group、school_line。只有具体专业或已核验专业组成员可建立专业—学校交叉关系。
- 河南 2025 单年专业组使用考生位次/最低位次：≤0.80 为保，>0.80 且 ≤0.95 为稳，>0.95 且 ≤1.15 为冲，超出不自动推荐；统一低置信，不与改革前文理科混算。
- 缺少可比年份时展示缺口与风险。当前没有地区偏好、自定义家庭权重或手动候选排序。
- 每份档案目前保存最新推荐快照；重新生成覆盖旧快照，完整规则/数据版本及历史留存尚待实现。

### 3.3 地图与学校详情

- 地图数字、名单截至日期、搜索分页来自接口，失败保留已加载结果并提供重试。
- 当前按省份、现有学校层次及校名/城市关键字浏览；没有单独的专业筛选接口。一本/二本是历史标签，不能当成全国统一招生资格。
- 地图、工作台、推荐结果与收藏中的学校统一打开右侧详情抽屉，手机使用全屏抽屉。
- 展示学校属性、定位解读、当前档案招生位置、风险缺口、已核验优势专业和来源。
- 招生信息保留省份、年份、科类、批次、招生粒度、最低位次、选科要求、置信度与来源。
- 官网/招生官网必须经过核验；缺失显示待核验。优势专业只使用正式证据，不能用旧 is_featured 标志冒充。
- 无档案也可看基础信息，档案区域显示建档提示；学校详情支持关闭按钮、遮罩、Esc 和焦点恢复，关闭不重置筛选/滚动。
- 地图、顾问、学校详情与维护页按需加载，不以提高包体警告阈值掩盖问题。

### 3.4 收藏与家庭讨论

- 专业收藏/排除、目标学校跟随档案保存在共享数据库；成功提示明确对应学生，刷新后保留。
- 从收藏重新进入统一学校详情；移除后各入口状态一致。
- 收藏备注最多 500 字，只辅助讨论，不改排序；切换收藏状态不得覆盖已有备注。
- 2—4 校紧凑比较使用统一详情事实；对比下方自动生成三行解释，AI 异常回退本地规则，不写聊天历史。
- 1—4 校可生成“给爸妈看”简报并复制纯文本，不产生公网分享链接；收藏和备注本身仍公开保存。

### 3.5 升学规划顾问

- 名称为“知向规划顾问”或“升学规划顾问”，不冒充真人、官方或授权数字分身。
- 使用仓库内锁定的安全改编方法论，不在运行时注入上游真人角色提示词。
- 上下文只含当前基础档案、工作台、收藏/排除、候选与可追溯事实；历史测评和家庭偏好不参与。
- 打开详情入口只预填草稿。第一次发送原子创建会话与用户消息，使用 clientMessageId 幂等重试；非法学校 ID 失败且不写历史。
- 同一会话使用滚动摘要和最近 16 条消息理解指代，但事实每轮重新从数据库读取，旧助手回答不是事实来源。
- 普通会话可以从本地 schools 唯一识别完整学校名或足够长的简称，持久化学校 ID、焦点名和标题；多义、过短称呼需澄清。
- 查询学校指访问本地数据库，运行时不联网补齐招生、就业、学费或住宿事实。
- 先回应当前问题；学校整体评价给有条件倾向，再解释目标专业证据、规划位次、调剂缺口、城市成本和学校层次。专业追问不重复学校通稿。
- 决策与事实问题明确“现在能确定 / 现在还不能确定 / 下一步只做”，最后只给一个可执行动作；问候、感谢、身份、记忆确认和单纯情绪不强套结构。
- 默认用普通家庭能理解的 4—6 句短答，复杂比较可展开；术语首次出现解释，不固定四段标题。
- 可以明确劝退某种选择，但不羞辱学生、家庭或收入，不把冲刺说成稳妥。
- 输出纯文本，事实链接由服务端 evidenceRefs 提供；历史 Markdown 只在前端非破坏性清理。
- AI 未配置、15 秒超时、限流、无效结构、Markdown、内部术语、无来源数字或越界承诺时回退同一意图的本地解释。
- 历史会话与消息分页；重发复用消息 ID；删除会话需二次确认。

### 3.6 报告

- 当前 PDF 即时生成并下载，不在 Supabase/Vercel 保存文件；读取基础档案与已保存候选快照。
- 没有快照时如实说明，不自动生成候选，不承诺包含完整收藏、排除和备注。
- 最终报告应与当前保存状态一致，完整保留来源、年份、规划位次、风险和免责声明；收藏备注一致性及完整版本留存是待完善项。
- 浏览器/字体需要在实际运行环境验证，特别是托管环境中文及 PDF 下载，不能用本地构建成功替代。
- 不导出 Word/Excel，不生成正式志愿表。

### 3.7 数据维护

- 学校数据质量页在 /admin/data-quality 直达，不进入普通导航；当前无网页 CSV 上传。
- 通用招生 JSON 脚本登记来源文件、SHA-256、逐行预检、人工确认、事务提交与按批次回滚。
- 预检也会写来源和批次等元数据；--commit 才提交正式招生记录。专用脚本不自动继承此预检行为。
- 正式名称或已核验别名才能自动匹配；模糊匹配、OCR 低置信与歧义保留待核验。
- 普通与特殊批次可共存；仅普通主批次、普通计划且有可靠位次的记录参与冲稳保。
- 学校链接自动发现只写 .scratch；人工核验后才显式导入，失败不得覆盖已有有效事实。
- 就业来源管理与同步路由限制 loopback；公开共享访问不代表可以从任意网络直接调用本机采集操作。

## 4. 数据来源与工程要求

1. 优先教育部、省级考试院，其次院校官方公开材料。
2. 官方文件无法稳定获取时，可补充使用明确标注官方来源且经过核验的公开镜像，并披露限制。
3. 搜索摘要仅用于发现入口；营销内容、自媒体和 AI 生成内容不进入正式事实。
4. 覆盖结论来自当次审计，区分 verified、unavailable、not_applicable、pending；缺口不填模拟值。
5. 输入显式校验，SQL 参数化；服务端密钥不进入前端、日志或提交。
6. Supabase 表开启 RLS，anon/authenticated 不直接操作业务表，业务读写经服务端完成。
7. 目标是档案存在校验、统一 JSON 错误和列表分页；现有例外见 API 文档，应独立修复，不默认为已满足。
8. 删除档案需用户明确操作并二次确认；测试只清理本次准确 ID，不按名称前缀扫描删除。

实际路由与参数统一见 [API](API.md)，环境与运行步骤见 [维护指南](MAINTENANCE.md)，验证命令见 [测试指南](TESTING.md)。

## 5. 待实现／待验收要求

以下仍保留为交付要求，不在使用文档中宣传为现有功能。详细状态由 SPEC 表维护：

- 档案复制、重命名和完整基础资料编辑；候选手动排序。
- 完整数据/规则版本与历史快照留存，PDF 与全部收藏/备注一致。
- AI 与 PDF 分别全站每日 200 次成功额度，北京时间零点重置、失败不扣额、耗尽禁用入口。
- Vercel 实际部署、域名、PDF 浏览器/中文字体及恢复演练的环境验收。
- 旧接口分页、档案存在检查与错误响应一致性。
- 历史端到端测试中固定数据数量和旧文案的清理，独立稳定测试数据环境。

这些项需单独任务实施，不恢复家庭偏好、测评、旧 Docker 或 MySQL 运行路径。

## 6. 验收场景

| 场景 | 应验证的行为 |
| --- | --- |
| 目标探索空成绩建档 | 不存 0、不创建空模考、不显示冲稳保 |
| 目标探索后增加有效全省位次 | 无需重建，自动开启学校与专业交叉候选 |
| 新模考只有分数 | 历史有效位次继续参与规划，不平均裸分 |
| 两步流程与历史偏好隔离 | 无测评/答题入口，旧测评 API 404；旧偏好值不改变候选或顾问 |
| 数据不足与改革隔离 | 少展示、披露年份缺口；河南改革前后不混算 |
| 三种招生粒度 | 仅具体专业及核验组成员进入专业—学校关系 |
| 学校详情各入口 | 使用同一抽屉，关闭保留筛选、滚动与焦点；移动端可用 |
| 收藏及备注 | 保存反馈明确，刷新保留，取消一致；备注不改排序 |
| 家庭比较与简报 | 2—4 校比较、1—4 校简报，来源和缺口可核对 |
| 顾问预填与会话 | 不自动发送、幂等重试、焦点持久化、唯一简称与指代有效、歧义不猜 |
| 顾问事实边界 | 正常与降级均无编造；决策三句话完整，普通聊天不强套 |
| 导入生命周期 | 标准 JSON 重复导入幂等，行数守恒，指定已提交批次可回滚 |
| 永久删除 | 二次确认，仅删除目标档案及关联记录 |
| PDF | 可下载、可打开、中文正常，内容与已保存快照一致；缺快照说明清楚 |
| 失败与未知 | 页面有加载/失败/空状态，缺事实不伪装成功，不显示内部错误和秘密 |

执行时记录通过、失败和未运行项；待实现功能只能标记未完成，不能按现状降低验收口径。
