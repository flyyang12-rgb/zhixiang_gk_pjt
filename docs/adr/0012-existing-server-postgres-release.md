# 现有服务器部署新版 PostgreSQL 应用

2026-09-26，用户明确要求把本轮实现提交GitHub并部署到此前实际使用的服务器，纠正了Vercel发布目标，并授权完成必要连接与部署操作，不重复询问。

现有服务器运行旧Docker/MySQL分支，新版main已经使用PostgreSQL。直接覆盖旧目录会使数据库和应用不兼容。因此新版采用独立目录、独立Compose项目和PostgreSQL数据卷；本地开发仍不依赖Docker。数据库访问继续由服务端pg负责，前端不持有连接串或AI密钥。

发布前在服务器受控目录备份旧数据库及知向代理配置。旧MySQL目录、容器和卷保留。首次新版数据库只能在全新空目标执行结构初始化与同服务器迁移；公共数据保留原始ID、来源、年份、审核状态及业务约束。为保持同一网站使用记录，同服务器迁移同时保留档案、收藏、模考、历史兼容记录和聊天；这些记录不离开原服务器，不上传Supabase，不进入Git、测试快照或普通日志。迁移必须逐表核对数量、校验外键和更新identity序列，事务失败不切换入口。

新版在独立loopback端口验证，再仅切换知向域名代理；回退恢复该代理即可重新使用保留的旧服务。切换后的新数据不自动反向合并MySQL，回退前必须考虑新写入并备份新版数据库。

本决策仅取代ADR0010中必须以Vercel/Supabase作为托管目标、以及不同运行环境不自动上传旧档案的部署选择；PostgreSQL、两步流程、公开共享、官方事实审核和AI仅解释边界保持。Supabase仍是可选PostgreSQL提供方，Vercel入口保留但关闭Git自动部署，详见[官方配置说明](https://vercel.com/docs/project-configuration/git-configuration)。

官方学习候选仍pending，不因上线变成审核通过。真实内容审核、家庭走查、每日额度及其他未交付功能继续按SPEC记录，部署成功不冒充完整产品验收。
