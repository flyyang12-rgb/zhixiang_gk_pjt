# ADR 0007：全批次存储，普通主批次推荐隔离

## 状态

Accepted — 2026-07-28

## 背景

家庭需要浏览本科、专科、提前批、专项、定向和征集等真实招生事实，但这些批次的资格条件和录取机制不同，不能直接与普通主批次混算冲稳保。旧业务键也无法可靠区分同校同年不同批次、计划和招生单元。

## 决策

`admission_programs` 保存全部已核验批次，并显式记录学历层次、招生类别、批次、计划类型、资格要求、原始名称和稳定 `record_key`。业务键包含学校、省份、年份、科类、学历层次、类别、批次、计划、粒度、代码及原始招生单元名称。

每条记录由确定性规则写入 `recommendation_eligible`。只有普通类主批次、普通计划且具有可靠最低位次的记录可以进入自动冲稳保；特殊或资格批次只在学校详情展示，并说明排除原因。规则引擎及所有候选查询必须显式过滤该字段。

导入采用来源文件清单、预检、人工确认、事务提交和按批次回滚。院校只允许正式名称或已核验别名匹配。审计状态独立记录 `verified / unavailable / not_applicable / pending`，避免“库里有记录”被误解为“全批次已完整”。

## 后果

- 能保留并展示不同制度和资格批次的事实，而不污染普通批次风险判断。
- 缺少官方文件时会形成明确待核验范围，覆盖率不会被硬编码或非空字段美化。
- 旧记录迁移后继续可用；新增来源必须提供完整批次语义和来源文件证据。
- 推荐查询遗漏资格过滤会构成高风险缺陷，必须由单元测试和三省端到端流程覆盖。
