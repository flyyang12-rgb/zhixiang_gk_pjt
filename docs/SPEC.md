# 知向高考志愿规划 MVP 规格

## Problem Statement

高考家庭需要在院校、专业、城市、就业和培养成本之间做复杂取舍。现有信息分散；仅凭分数或大模型直接给结论，无法保证数据真实、结果稳定或理由可追溯。家庭需要一个基于官方录取记录、能够解释候选清单但不承诺录取的本地工具。

## Solution

知向提供一个供亲友通过网址共同使用的两步志愿规划流程：“基础信息 → 专业与学校”。家庭创建学生档案后直接进入“专业与就业工作台”，不设置测评、答题或家庭偏好环节。工作台先按选科硬过滤，再从数据库已审核的专业证据池中展示最多 9 个专业（优先了解、值得比较、谨慎报考各最多 3 个）和每专业最多 3 个就业方向。院校专业组省份将学校/专业组位次候选与具体专业交叉匹配分层展示：只有官方组内专业目录完成核验后才建立具体专业关系。规则引擎拥有生成、排序和风险分层权；升学规划顾问只能解释工作台已有结果，不得新增、改序或改变冲稳保。结果可收藏、排除、保存为目标院校并用于家庭讨论。

产品同时支持一年期的家庭陪跑：主要操作者记录模考坐标，弟弟选择愿意继续了解的专业和学校，父母只确认成本、培养年限和最差就业出口等风险底线。这些能力均收在现有工作台与收藏弹层内，不新增第三步，不恢复家庭偏好问卷。

## User Stories

1. As a 家长, I want to 创建学生档案, so that 我可以持续保存和调整一次完整的志愿规划。
2. As a 家长, I want to 管理多个学生档案, so that 同一台电脑可以服务不同学生而不混淆数据。
3. As a 家庭, I want to 永久删除学生档案, so that 本地不再保留不需要的个人与家庭信息。
4. As a 学生, I want to 在志愿填报阶段填写省份、科类、分数和位次, so that 系统能够定位我的录取竞争位置。
5. As a 学生, I want to 在没有分数和位次时进入目标探索模式, so that 我仍能了解专业和学校但不会看到伪造的成绩或冲稳保。
18. As a 家庭, I want to 查看全国院校地图, so that 我们能理解院校层次和地区分布。
19. As a 家庭, I want to 按院校层次、城市、专业和名称筛选, so that 我们可以快速缩小关注范围。
20. As a 家庭, I want to 查看院校面向当前省份的招生单元, so that 学校展示与实际可填报范围一致。
21. As a 家庭, I want to 查看地区建议, so that 我们能比较城市机会、生活成本、距离和产业条件。
22. As a 家庭, I want to 把地区偏好作为评分因素, so that 系统不会因普通偏好直接排除明显合适的院校。
23. As a 家庭, I want to 设置必须省内或不接受某地区等硬约束, so that 候选严格遵守不可妥协条件。
24. As a 家庭, I want to 单独查看院校候选, so that 我们可以先比较学校平台、位置和历史录取表现。
25. As a 家庭, I want to 单独查看专业候选, so that 我们可以先讨论兴趣、选科、培养和职业路径。
26. As a 家庭, I want to 查看交叉匹配, so that 最终候选只包含院校实际开设且面向本省招生的专业或专业组。
27. As a 家庭, I want to 获得冲刺、稳妥和保底候选, so that 我们能按风险层次组织候选清单。
28. As a 家庭, I want to 查看每个候选的依据与风险, so that 我们知道位次、年份、选科条件和数据缺口如何影响结果。
29. As a 家庭, I want to 查看推荐置信度, so that 数据缺失或历史波动不会被包装成确定答案。
30. As a 家庭, I want to 收藏、排除和调整候选顺序, so that 候选清单能反映我们的最终讨论。
31. As a 家庭, I want to 看到每所院校的匹配专业和不推荐专业, so that 我们不会只凭学校名称做决定。
32. As a 家庭, I want to 查看录取记录的数据来源和年份, so that 我们可以核对关键事实。
33. As a 家庭, I want to 向升学规划顾问追问, so that 我们可以理解院校、专业和城市之间的取舍。
34. As a 家庭, I want to 让顾问读取当前学生档案和候选清单, so that 回答与当前决策上下文一致。
35. As a 家庭, I want to 在顾问不知道事实时看到明确说明, so that 我们不会把编造内容用于填报。
36. As a 家庭, I want to 在 AI 不可用时继续使用规则结果, so that 模型连接失败不会阻断志愿规划。
37. As a 家庭, I want to 导出 PDF 报告, so that 我们可以离线讨论、打印并保留当前决策依据。
38. As a 数据维护者, I want to 预检标准 CSV, so that 错误或冲突数据不会直接进入正式数据版本。
39. As a 数据维护者, I want to 查看导入报告, so that 我知道新增、更新、跳过、缺失和异常记录数量。
40. As a 数据维护者, I want to 回滚一次导入, so that 错误数据版本可以被撤销。
41. As a 数据维护者, I want to 重复导入同一数据而不产生重复记录, so that 更新流程可以安全重跑。
42. As a 家庭, I want to 看到公开共享说明, so that 我知道档案和聊天会被所有访客看到、修改或删除。
45. As a 家庭, I want to 从专业或院校详情开始独立顾问会话并返回原处, so that 每次讨论对象清楚且可以继续查看历史记录。
46. As a 家庭, I want to 在同一顾问会话中持续追问, so that 顾问能记住前文的条件、对象和未解问题。
47. As a 家庭, I want to 看到通俗、有人情味且敢于说清风险的解释, so that 学生和不熟悉志愿术语的父母都能一起做决定。
48. As a 家庭, I want to 分页查看、重试或删除顾问会话, so that 历史记录可控且失败不会造成重复问题。
43. As a 家庭, I want to 在收藏中并排比较 2—4 所院校, so that 我们能集中查看城市、层次、招生位置和数据缺口。
49. As a 哥哥, I want to 记录每次模考的分数与全省位次, so that 家里看到成长坐标而不把趋势当成高考预测。
50. As a 家庭, I want to 在收藏的专业和学校下留讨论备注, so that 弟弟的意愿、父母的担心和待核验问题不会丢。
51. As a 家庭, I want to 把 1—4 所收藏学校整理为手机一页简报并复制纯文本, so that 父母无需学习系统术语也能参与讨论。
44. As a 数据维护者, I want to 查看院校事实覆盖率和待核验清单, so that 缺失官网、招生网、招生年份或优势专业可以被安全补全。

## Implementation Decisions

- 前端采用 Vue 3、TypeScript、Vite 和 ECharts；后端采用 Express、TypeScript、Zod 和 `pg`；正式数据统一保存在新加坡区域的 Supabase PostgreSQL。
- 浏览器不直接连接 Supabase，只通过 Express API 读写。服务端使用 `DATABASE_URL`、TLS 和小连接池访问数据库；旧 MySQL 与 Docker Compose 部署路径退役，后续由 Vercel 托管网站与 API。
- 产品不提供注册、登录或档案归属隔离。所有访客都能查看、修改和永久删除全部学生档案、收藏、推荐结果及顾问聊天；这是明确选择的公开共享模式，不得在页面或文档中暗示为私密空间。
- 学生档案是志愿规划的数据边界，拥有基础信息、候选清单、收藏排除项和顾问会话；历史问卷与家庭偏好数据继续保留但不参与当前流程。
- 主流程固定为“基础信息 → 专业与学校”，不提供测评或答题入口。AI 只能解释规则结果，不参与生成、排序、分档或风险判断。
- 当前版本不收集家庭偏好或自定义权重；候选只使用明确的选科硬条件、当前省份/科类、位次和可追溯证据。
- 候选生成顺序固定为招生单元候选、专业证据、交叉匹配和收藏清单。交叉匹配必须验证招生单元在当前省份、年份和科类下有效。
- 目标探索建档不要求分数或位次，只使用称呼、省份、科类和选科完成基础档案；空成绩保持为未知，不保存为 0，也不创建空的建档坐标。规则引擎使用位次作为主要指标，结合近三年可比录取记录和数据波动生成稳定结果；缺少可靠位次时进入目标探索，不估算冲稳保。档案原始模式只作为建档阶段记录，只要历史模考形成规划位次，工作台就自动先展示学校冲稳保，再展示专业方向及可核验学校，不要求重新建档或手动切换模式。
- 招生记录必须区分具体专业、院校专业组和学校线。河南 2025 只使用同制度专业组记录生成低置信冲稳保：考生位次/专业组最低位次不高于 0.80 为保、0.80—0.95 为稳、0.95—1.15 为冲，超过 1.15 不自动推荐。该结果不与改革前文理科混算；缺少官方组内目录时不得把专业组名称当作具体专业。
- 就业数据采集采用“维护者明确手动触发”模式。API 进程和浏览器启动时只读取数据库中已有统计，不自动访问外部来源、不启动定时采集。数据超过 7 天、健康来源少于 2 个或质量异常时仍按降级规则停止就业排名，不用自动采集掩盖过期状态。
- 专业排序同时参考当前与未来，但只接受可审计证据：近期招聘覆盖 30%、本科直接就业入口 20%、当前位次可达院校 25%、近期需求稳定性 10%、未来发展证据 15%。未来证据必须来自政府主管部门或同级权威公开文件，保存发布方、年份、来源、核验时间和有效期；过期或未覆盖时保持未知。至少两个独立因子有效且证据权重覆盖达到 50% 才展示综合参考分，否则只展示“暂不评分”，未知不得转换成 0。
- 专业候选池由数据库中具备已审核岗位方向或有效未来证据的专业动态生成，不在路由中写死专业代码；证据不足时可以少于 9 个，并披露当前已审核专业数，不宣称覆盖全部本科专业。
- 候选清单目标数量约为冲刺 6、稳妥 12、保底 6；有效数据不足时返回实际数量，不使用模拟记录补齐。
- 每次生成候选清单时记录数据版本、规则版本和生成时间，保证报告可复现。
- 顾问通过 OpenAI 兼容接口运行。它可以追问、解释、比较和建议调整，但不能创建、删除或改变规则引擎给出的候选等级。收藏中选择 2—4 所院校后，对比卡片下方自动给出“优先核对、关键差异、填报风险”三行分析；只使用当前档案与已核验事实，不写入顾问会话，AI 不可用时回退本地规则分析。
- 从专业或院校详情进入顾问时每次创建新会话，前端只提交专业 ID 或院校 ID 与用户确认后的问题；服务端重新读取对应工作台/院校证据。详情入口创建的结构化焦点会话固定讨论对象；普通会话没有焦点时，可在用户明确提到一所可唯一确认的院校后获得院校焦点。消息保存在 Supabase 的公开档案中，可从历史会话重新打开；返回时恢复当前会话的专业或院校详情。打开顾问只预填，不自动发送。
- 打开顾问时先建立前端草稿，用户首次发送后才持久化正式会话；未发送的草稿不进入历史。同一会话每轮携带记忆摘要和最近 16 条消息，但当前档案与已核验证据始终优先于旧聊天。
- 普通会话中的院校名称识别只查询 Supabase 院校库：完整名或足够长且只命中一所院校的简称才能建立焦点；过短或命中多所时不得猜测。识别成功后将正式院校名与 ID 保存到会话，后续“它、这个学校”按该焦点理解。这个搜索只用于识别实体和读取已核验事实，不代表运行时联网补齐招生或就业信息。
- 顾问每轮先识别用户是在问、担心、反驳还是犹豫，再直接回应当前这句话。问候、情绪、身份确认和单点问题使用自然对话，不强制标题、不机械复述前文，也不展开无关档案；复杂比较可以自然分段，但四段标题不是固定模板或安全校验条件。所有判断按“鲜明倾向 → 硬依据 → 最大误区 → 一个关键追问”展开，第一句必须先亮态度。院校判断在硬条件通过后固定按“目标专业的具体招生与优势证据 → 规划位次和招生风险 → 调剂与证据缺口 → 城市和培养成本 → 学校层次与名气”比较；专业优先不等于把冲刺说成稳妥，风险更高时必须同时保留同专业的稳妥或保底候选。允许明确站队、直接劝退并把无证据的选择说成“不划算”或“在赌专业”，但不得贬低学生、父母、家庭收入或出身。默认用家长和高中生都能一次听懂的 4—6 句短答，术语首次出现时立即用日常语言解释。
- 学校、专业、就业、考研、报考判断和具体事实回答统一在顶部展示“现在能确定 / 现在还不能确定 / 下一步只做”三句话：第一句只能使用当前已核验事实，第二句必须点明具体缺口，第三句只允许一个家庭可执行动作。问候、感谢、身份说明、记忆确认和单纯情绪回应不套该结构。聊天正文不得显示 Markdown 标记或“综合参考分、低置信度、本科直接就业入口分”等内部术语。
- 学校焦点只限定事实范围，不得把每轮问题替换成同一份学校介绍。用户表达目标专业时，应核对该校是否有该专业的具体招生证据；用户指出重复、答非所问或没听懂时，先承认并结合本会话最近的用户目标重新回答，不得再次返回原模板。
- AI 请求最长 15 秒；超时、限流、无效结构或越界输出自动切换同语气的本地解释。消息使用客户端唯一 ID 幂等重试。
- 会话与消息列表强制分页；用户可在二次确认后删除单个会话。桌面端使用历史侧栏，移动端使用可恢复焦点的底部弹层。
- 上游公开 Skill 只提取就业倒推、中位结果、家庭承受能力、城市机会和数据优先等方法。运行时不加载真人扮演、侮辱性表达、争议传播或实时联网搜索指令。
- 地图、工作台、推荐结果和收藏统一使用学校详情抽屉；收藏支持选择 2—4 所学校进行紧凑比较，比较数据仍来自统一详情接口。地图展示的院校名单截至日期必须来自当前正式导入来源并与数据批次绑定，不得在前端硬编码或用请求时间冒充；首次加载、搜索和分页失败时保留已有结果并提供中文重试入口。
- 模考轨迹保留每次原始坐标；最新记录是当前坐标并同步档案分数/位次。学校与招生单元推荐使用最近最多 5 次有效全省位次的中位数作为“规划位次”，并披露有效次数、区间与稳定度。只有 1 次时继续可用但明确标注单次参考；最新记录只有分数时，历史有效位次仍可继续形成规划位次；没有位次的分数不参与计算。不外推高考成绩或录取概率。
- 收藏备注是用户提供的家庭讨论条件，最长 500 字，不参与专业排序、候选生成或冲稳保；切换收藏状态不得覆盖已有备注。
- 收藏中可选 1—4 所学校生成“给爸妈看”简报。简报仅展示态度、两个硬依据、最大风险、家庭备注和一个核验动作；没有规划位次时说“等可靠位次后再判断报考位置”，已有规划位次时可讨论学校历史位置，不受档案原始模式阻断。手机端全屏，桌面端窄弹层，只支持复制纯文本，不另生成分享链接。
- 院校官网自动发现只生成本地候选报告；显式导入后才可进入详情。优势专业必须有官方专业名称、认定类型、发布方、官方来源和核验时间；逐专业认定年份缺失时只展示综合名录年份，不得把名录年份冒充认定年份。
- 地图/ECharts、顾问、学校详情和维护页使用异步组件按需加载，不能通过提高构建警告阈值掩盖首屏体积。
- 顾问使用锁定提交版本并经人工审核的公开 Skill 方法论，不显示真人姓名作为顾问名称，不冒充本人或官方服务。
- 全国院校基础数据来自教育部；招生与录取数据来自河南、山东、河北考试院及院校招生官网。非官方来源不能进入正式数据版本。
- 管理导入采用预检、确认、回滚三阶段；确认后的导入创建新数据版本，重复记录通过业务唯一键更新。
- 招生事实全量保存学历层次、招生类别、批次、计划类型、资格要求、原始院校/招生单元名称和稳定业务键。普通主批次且具备可靠位次的记录才允许进入冲稳保；提前批、专项、定向、征集和其他资格批次只在学校详情浏览。
- 数据完整性按审计范围闭环，而不是按字段非空率判断。三省 2023—2025 每个本/专科范围以及逐校官网、招生网、优势专业、招生覆盖均记录 `verified / unavailable / not_applicable / pending`、原因、来源和核验时间；`pending` 必须对用户披露，不能解释成已覆盖。
- 招生导入固定经过来源文件登记和校验值、逐行预检、人工确认、事务提交与目标批次回滚。正式院校名和已核验别名是唯一允许的自动匹配方式；模糊匹配、OCR 低置信和歧义别名只能进入待核验清单。
- 当前审计快照仍只有三省本科主批次记录；专科、特殊批次、河南 2023/2024 完整记录及河南 2025 专业组成员等范围保持 `pending`，取得并核验官方文件前不得宣称全量完成。
- REST API 使用统一 `{ success, data, error, requestId }` 响应，所有输入经 Zod 校验，所有 SQL 使用参数化查询，列表接口强制分页。
- PDF 由后端根据已保存的学生档案和候选清单生成，内容不得依赖浏览器中尚未保存的临时状态。
- PDF 即时生成并直接下载，不保存在 Supabase 或 Vercel。
- AI 顾问与 PDF 生成分别设置全站每日 200 次成功额度，按北京时间零点重置；失败不扣额度，平时不展示余量，耗尽后禁用对应入口并提示次日再试。额度计数随公网部署实现。
- 数据库连接串与 AI 密钥仅存在服务端环境变量中，不返回前端、不写入日志。

## Testing Decisions

- 主测试接缝是浏览器完整用户旅程：使用固定 PostgreSQL 测试数据版本和可预测的 AI 替身，从创建学生档案一直验证到生成候选清单及下载 PDF。测试只断言用户可观察的页面、下载内容和持久化结果，不断言组件或函数内部实现。
- 第二测试接缝是数据导入 HTTP 接口：使用小型官方格式样本验证预检、确认、幂等和回滚，因为批量数据错误无法仅通过普通用户旅程充分覆盖。
- 规则引擎通过公开服务接口测试稳定性：相同档案、数据版本和规则版本必须得到相同候选等级与排序。
- 测试覆盖两步主流程、位次缺失、数据不足、不同招生粒度以及选科硬约束冲突。
- 测试覆盖真实位次、缺少位次的目标探索、缺少历史年份、历史位次大幅波动、无有效招生单元和候选不足目标数量。
- 测试覆盖数据库不可用、AI 超时、AI 返回无效结构、PDF 生成失败和 CSV 字段异常；失败必须显示中文提示且不泄露内部信息。
- 顾问测试断言引用的数据存在于测试数据版本、缺失事实被明确拒答、回答不冒充真人，并且无法改变规则引擎结果。
- 专业/院校顾问测试覆盖结构化焦点、非法 ID、新会话、不自动发送、历史消息、后续追问继续关联和返回原详情；还必须覆盖普通会话中途识别唯一院校简称、持久化焦点、指代追问和过短/歧义称呼不猜测。历史偏好有值或无值不得改变候选、顾问上下文或 PDF。
- 顾问 V2 额外覆盖长会话摘要、当前事实优先、温暖直白语气、家庭羞辱禁词、15 秒超时降级、幂等重试、分页、删除、移动端历史与旧消息幂等迁移。
- 当前仓库没有既有测试框架或可复用测试先例；实施时优先建立少量端到端测试和导入接口测试，不为每个内部函数增加脆弱单元测试。

## Out of Scope

- 用户注册、登录、家庭权限隔离和支付。
- Docker、本地桌面安装包和移动 App。
- 面向陌生用户的多账号运营、监控告警和付费服务；当前仅按亲友范围公开共享。
- 河南、山东、河北以外考生的完整录取推荐。
- 自动生成或直接提交省考试院正式志愿表。
- Word、Excel 导出和多人协同编辑。
- 使用 AI 直接计算录取等级、修改候选清单或生成无来源招生事实。
- 使用真人姓名、肖像、声音或官方身份进行顾问宣传。
