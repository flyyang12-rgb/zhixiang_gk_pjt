# 知向 · 高考专业与学校探索

<p align="center">
  <img src="assets/readme/overview.svg" width="100%" alt="知向的两步流程：基础信息，然后探索专业与学校；无可靠位次先了解学习证据，有位次后开启招生比较。">

帮助高中生与家长看清专业学什么、有哪些职业门槛，再用可核验的招生资料比较学校。**无可靠位次先探索，有位次后再判断报考位置。** AI只解释已有证据，不替学生选专业，不编造招生事实。

[使用指南](docs/USER_GUIDE.md) · [本地启动](#本地启动) · [服务器部署](docs/SERVER_DEPLOYMENT.md) · [开发与测试](docs/TESTING.md) · [规格与进度](docs/SPEC.md)

> **公开共享：** 无需注册。所有访客都能查看、修改和永久删除全部学生档案、收藏、备注和顾问聊天。只填写愿意公开的信息。

## 两步完成，探索可以持续

**1. 基础信息。** 选择省份、科类与选科，建立档案。默认目标探索；分数和可靠全省位次可以暂时留空，不把缺失成绩记成0。

**2. 专业与学校。** 所有浏览、比较、收藏、备注和顾问操作都在工作台完成，没有测评、答题、家庭偏好问卷或第三步。

| 当前情况 | 可以做什么 | 判断边界 |
| --- | --- | --- |
| 没有可靠全省位次 | 浏览清单和分页目录，核对课程/活动/职业资料，收藏或排除方向，记录讨论 | 不显示综合分、三档、冲稳保或录取预测；未知选科要求不当作不限 |
| 关注了多个专业 | 选择2—3个比较；选择1—3个生成专业探索简报，复制给家人讨论 | 逐项注明学校、材料年份和来源，不选赢家，不给个人适合度 |
| 后续形成可靠位次 | 自动开启学校与专业联合比较，保留收藏、排除、备注和会话 | 最近最多5次有效全省位次取中位数；不平均裸分，不外推高考成绩 |

从地图、工作台或收藏打开学校，使用同一个详情抽屉。学校比较支持2—4校，学校家庭简报支持1—4校；它们与专业学习简报分别表达依据。

## 每条结论都能追到依据

- **学习材料：** 只读取审核通过、当前有效的官方资料；保留原文位置、发布方、材料年份、核验时间及适用学校/专业范围。课程先修与高考招生资格分开。
- **更新与撤回：** 详情、比较、简报重新生成及顾问每次发送，都读取当前有效材料；资料撤回后保留收藏和原始备注，旧事实不再作依据。
- **招生资料：** 院校名单及部分山东、河南、河北2023—2025记录可用，不代表全部年份、科类和批次覆盖。具体专业、专业组和学校线分开，制度不同的年份不混算。
- **学校官网与优势专业：** 仅展示经过核验的事实和链接；没有数据就说明缺口，不猜域名、不从组名猜专业。
- **就业样本：** 近期公开岗位覆盖不等于就业率或收入保证。健康来源少于2个、超过7天或质量异常时，停止就业排名，学习证据仍可浏览。
- **规划顾问：** 入口只预填，首次发送才保存会话。AI未配置、超时或回答越界时，回退同问题的本地解释；首屏外专业也可作为审核材料焦点。

所有结果仅用于分析与家庭讨论，不构成录取、就业、收入或升学承诺。

## 本地启动

需要 **Node.js 22.x（22.12+）和npm**。已有`.env`时不要覆盖；仅首次从`.env.example`复制并填写服务端数据库配置。

```powershell
npm ci
Copy-Item .env.example .env # 仅首次执行；已有 .env 时跳过
# 编辑 .env，填写独立开发 PostgreSQL 连接
npm run dev
```

也可以双击`setup-local.cmd`安装依赖，再双击`start-local.cmd`启动。脚本不检查数据库连通性或安装浏览器。

- 网页：`http://localhost:5173`
- API：`http://localhost:3000`
- 健康检查：`http://localhost:3000/api/health`，应返回`database: "connected"`

数据库通过服务端`DATABASE_URL`访问，兼容本机PostgreSQL与Supabase；不要添加`VITE_`前缀，浏览器不持有连接串或AI密钥。日常启动无需重复初始化已有库。独立空库的初始化、审核导入与故障处理见[维护指南](docs/MAINTENANCE.md)。

配置外部AI后，仅发送回答所需的最少档案与会话上下文；真实密钥不得进入Git、日志、截图或前端。模型名需与所用服务实际可用模型一致。

## 技术与部署

**Vue 3 + TypeScript + Vite + ECharts → Express 5 + Zod → PostgreSQL。** 确定性规则在服务端生成结果，前端负责展示与交互；浏览器只访问API。

当前部署在用户现有Linux服务器，使用独立Docker Compose项目承载新版网页、API与PostgreSQL。2026-09-27按明确授权删除旧MySQL目录、容器和数据卷，随后按用户要求清理旧备份与过期发布，保留当前数据库和新档案。后续更新复用新版数据卷，不重复清空。部署、健康验证和恢复边界见[服务器部署指南](docs/SERVER_DEPLOYMENT.md)。本地开发不需要Docker。

`api/index.ts`和`vercel.json`保留为已有可选入口；**本次不使用Vercel发布**。Supabase可作为PostgreSQL服务使用，不是此次发布所依赖的唯一数据库。

```powershell
npm test
npm run build
npm run test:e2e:exploration
```

探索浏览器验证先按[测试指南](docs/TESTING.md)注入独立`EXPLORATION_UI_TEST_DATABASE_URL`。专用端口3104/5174不复用日常服务，每次另建随机准确测试库，结束只清理本次ID与数据库。默认完整`npm run test:e2e`会写数据库，必须另行准备独立环境。
